版本與分支

分支：在旁邊開一條路

clone、commit、push 你已經天天在用。這一課補上它們底下的樣子：檔案在 Git 裡經過哪三個區，以及分支怎麼讓你改東西時不動到正在用的版本。

1三個區：改了、挑好、存檔

改輪值網站時動了三個檔，其中 debug.txt 是除錯留下的。依序按下面三個動作。

工作區

暫存區

儲存庫

先按「改檔案」。

中間這個暫存區，就是讓你「挑」：同一天改的東西不一定都該存成同一個版本。用 git add . 一次全加，就會把除錯檔、甚至密碼檔一起存進去。

放資料庫密碼的設定檔（例如 config.php）要列進 .gitignore。一旦 commit 又推上公開的 GitHub，就算之後刪掉，歷史裡還找得到，只能去換密碼。
看不懂就回來說 分支 1

2分支是一張可以移動的書籤

分支不是把整個專案複製一份，只是一個指向某個版本的名字；HEAD 標出你現在站在哪一條。依序按按看。

網站如果是從 main 發佈的（像 GitHub Pages），分支上做多少都不影響線上；確定沒問題再合併，網站才更新。

看不懂就回來說 分支 2

3雲端做的分支，怎麼回到電腦

在雲端 session 讓 AI 開分支做事，做完推上 GitHub；回到自己電腦，再把它拉下來接著用。照順序按：

雲端 session
GitHub
你的電腦
雲端 session 在新分支上做好了，還沒推。

fetch 只把 GitHub 上的新東西抓下來看，不動你正在用的檔案；pull 則是「fetch 再合併進目前這條分支」。不確定別人做了什麼時，先 fetch 比較安全。

看不懂就回來說 分支 3

4衝突：兩邊改了同一行

你在 main 上改了首頁標題，分支上的 AI 也改了。Git 合併時，只要改的是不同行就自動合好；同一行兩種寫法，它不會替你選。

標記之間 <<<<<<< 到 ======= 是你這邊、======= 到 >>>>>>> 是要合進來的那邊。挑好、刪掉標記，再 add、commit 就完成。分支開得越久越容易衝突，所以小步做、早點合。

看不懂就回來說 分支 4
