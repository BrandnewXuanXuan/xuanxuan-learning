資料表變大以後

表、欄、主鍵、CRUD，你在 phpMyAdmin 裡已經操作過。這一課講資料變多、使用的人變多以後才會冒出來的四件事：速度、半途而廢、惡意輸入、誰能看什麼。

1索引：不用一頁一頁翻

要找出某一天的值班紀錄。沒有索引，資料庫只能從第一筆看到最後一筆；有索引，它像查字典一樣跳著找。拖動滑桿讓資料變多：

值班紀錄有幾筆
沒索引
有索引

長條是「要看幾筆」的比例（示意）。索引不是免費的：每次新增、修改，索引也要跟著更新，也佔空間。所以只替常拿來當查詢條件的欄位加，在 phpMyAdmin 的「結構」頁就能看到、新增。

2交易：要嘛全做，要嘛全不做

小明和小華換班，資料庫要做兩件事：刪掉小明的週六、把小華加到週六。如果做到一半主機斷線呢？

MySQL 的交易要資料表用 InnoDB 引擎才有效；舊的 MyISAM 會默默忽略。phpMyAdmin 資料表清單的「類型」欄看得到，用的是 MyISAM 就請 AI 幫你評估轉換。

3把輸入塞進 SQL，等於讓別人寫 SQL

查詢某人的班表時，如果直接把輸入框的文字黏進 SQL 字串，有人就能輸入一段「看起來像 SQL」的東西改掉整句的意思。試試兩種輸入：

參數化查詢（PHP 的 PDO prepare，7.0 就有）把「SQL 的句型」和「使用者給的值」分兩次送：值永遠只被當成值，不會變成指令。同樣的道理，把使用者輸入顯示到網頁上時要用 htmlspecialchars 跳脫，免得被塞進可執行的程式碼。

4誰能看哪幾列，寫在哪裡

值班表裡有手機號碼。不同的人打開，應該看到不一樣的東西。切換身分：

你現在的網站，權限判斷寫在 PHP 裡，資料庫密碼放在主機上，訪客碰不到資料庫。Easy-Vibe 中級篇介紹的 Supabase 這類服務不同：網頁直接連資料庫，連線用的金鑰放在前端、誰都拿得到，所以權限必須寫在資料庫本身（叫做 RLS，列層級安全）。之後換架構時，記得權限要跟著搬家。
