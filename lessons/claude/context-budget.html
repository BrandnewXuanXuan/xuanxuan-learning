context 與額度

一次對話的帳單

為什麼同一句話，早上問很便宜，聊到晚上問就很貴？答案藏在每次送出時，Claude 實際讀了什麼。

圖裡的「格」是示意單位，用來比大小，不是實際的 token 數。

1每次送出，整疊重寄一次

Claude 不會「記得剛剛聊過什麼」。每次送出，Claude Code 都會把設定和整段對話疊在一起重新寄出；Claude 每用一次工具（讀檔、跑指令），拿到結果後又會再寄一次。

按「問一句」，看左邊越疊越高、右邊越長越高。

多按幾次就會發現：右邊只會越來越高。讀大檔案特別貴，因為檔案內容會一直留在對話裡，之後每一次都要跟著重讀。疊到虛線框（快滿了）時，Claude Code 會自動壓縮，把舊對話濃縮成一塊摘要；但壓縮本身要先讀完整疊，所以也是一次大請求。

看不懂就回來說 帳單 1

2快取：重讀變便宜，但會過期

重讀的部分如果還在快取裡，價格便宜很多，大約原價的一折。但快取有時效：訂閱方案大約一小時；改用額外購買的用量時，只剩五分鐘。

離上一則訊息過了多久10 分鐘

假設前面已經累積 30 格對話，下一則訊息本身 2 格（為了好比較，省略寫入快取的費用）。所以休息很久之後，回到一個很長的 session 繼續問，是最容易不知不覺吃掉額度的情況。這時開新 session，或從摘要接續，通常比較划算。

看不懂就回來說 帳單 2

3誰常駐、誰用到才進來

不是所有設定一開始就塞進去。點下面的按鈕，看哪些東西用到時才進來。

context 視窗
灰色紙條每次都在；彩色紙條是用到才放進來的。

由此可以推出兩個原則。第一，CLAUDE.md 要短：它每次都在，官方建議控制在 200 行以內，只有特定工作才需要的規則，就搬到 skill 或子資料夾。第二，在 CLAUDE.md 裡用 @檔案 匯入不會省空間，只是方便整理，啟動時一樣全部讀進來。

看不懂就回來說 帳單 3

5看自己的帳

/usage

看用量條，以及最近的用量被誰吃掉：哪個 skill、subagent、MCP 伺服器各佔多少。佔超過一成的耗量行為（例如長 context、快取沒命中）會被特別標出來。

/context

看這個 session 的空間現在被什麼佔掉。

/insights

分析你最近的使用習慣，產出一份報告。注意：跑這個本身也會用到額度。
