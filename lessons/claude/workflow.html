開發少繞路的四個習慣

Claude Code 官方的最佳實踐，加上團隊在正式環境的用法，整理成四個習慣。每一個都是為了同一件事：讓 Claude 少走冤枉路，你少花時間收拾。

1先探索、規劃，再動手

大一點的工作，先用 plan mode（規劃模式）讓 Claude 探索、提出做法，你確認後再實作；小改動直接做就好。選看看：

最關鍵的一步是給它驗證的方法：測試、建置、截圖比對。能自己檢查，它才知道什麼時候算做完，你不在旁邊盯著時也收得了尾。另外記得：context 越滿表現越差，換工作就 /clear，大量探索交給分身。

2auto mode：讓分類器幫你把關

Auto mode 現在是 Claude Code 的預設：不再每個指令都問你，而是由一個分類器逐一判斷，只擋下看起來有風險的動作。內部評估中，它抓到的危險動作比開發者手動點「允許」時還多；Claude 被打斷前能連續工作的時間，大約是以前的 9 倍。按下面看一串動作怎麼被處理：

團隊的做法：日常開發交給 auto mode，但在設定裡直接禁止最危險的指令（例如遞迴刪除）；碰到正式環境、別人的工作（例如替別人審 PR），就改回逐一確認。也有人設定成：代表自己對外發言（發 Slack、寄信）一律不自動放行。

3雲端 session：一件事一台機器

claude --cloud "要做的事" 會把工作丟到雲端的獨立機器上跑，每件事各自一條分支，彼此不會搶資源、改到同一批檔案。點工作看該放哪裡：

要注意：私人 repo 除了登入 GitHub，還要裝 Claude 的 GitHub App，這是兩件不同的事。平行的雲端 session 彼此不知道對方改了什麼，合併時要留意衝突。

4超過一百行，改用 HTML

Claude Code 團隊發現：Markdown 超過一百行就很難讀。改請 Claude「做成一個 HTML 檔」，就能放表格、圖、可以操作的滑桿，傳個連結就能分享。切換看看同一份「方案比較」：

適合做成 HTML 的：比較好幾個方案、審查程式變更、解釋一段程式、設計原型、報告與圖解，還有臨時的編輯介面，調整完按一下就能把結果複製回對話。你正在看的這個網站，就是同一個想法。
